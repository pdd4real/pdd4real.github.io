AutoDL 无卡模式下载模型权重反复 Killed：新版 hf CLI 的 Xet 触发 OOM

发表于 2026-08-11 分类于 Linux
在 AutoDL 无卡模式实例上用新版 hf CLI 下载模型权重，进程反复被 Killed 的完整排查记录：dmesg 查不到内核日志，最终通过 cgroup 内存上限确认根因是 Xet 并行下载把 2GB 内存撑爆，并给出关闭 Xet 的解决方案。

记录一次在 AutoDL 无卡模式实例上下载模型权重的排障过程：SAM 权重用 wget 一次下完，SD v1.5 用新版 hf CLI 却反复被 Killed。排查从 dmesg 无输出（容器拿不到内核日志）开始，转到 cgroup 内存上限确认，最终定位到 huggingface_hub 1.x 默认启用的 Xet 并行下载在内存中堆积分块，超过 2GB 上限触发 OOM killer。给出 HF_HUB_DISABLE_XET=1 的解决方案，并整理了无卡模式 2GB 内存上限对后续操作的影响。

背景

在 AutoDL 租了一个实例做 LayeredVectorization 项目复现，需要下载两个模型权重：

  • SAM（sam_vit_h_4b8939.pth，约 2.6GB），用 wget -c 下；
  • SD v1.5（runwayml/stable-diffusion-v1-5，约 4.3GB），用新版 hf CLI 下。

实例开的是无卡模式（不占用 GPU，仅做下载、配环境），数据盘 /root/autodl-tmp 在实例切换间持久化。下载命令统一指定 --local-dir 落数据盘。

现象

  • hf download 下载速度很快（十几 MB/s），但下到中途进程被 Killed（SIGKILL）。
  • 最初和 SAM 的 wget 并跑时被 Killed，一度以为是两个下载抢占内存；但 SAM 下完后单独跑 hf，仍然被 Killed。
  • 对比：SAM 2.6GB 用 wget 一次成功，从未出问题。

排查

第一步：dmesg 查 OOM 记录，无输出

无输出。AutoDL 是容器环境，容器内拿不到宿主机内核环形缓冲区，dmesg 要么被限制要么为空，这条取证路径直接断掉。

第二步：cgroup 确认内存上限

容器内存被 cgroup 限死，直接读限制文件：

输出 2147483648，即 2 GiB。无卡模式给整个容器就 2GB 内存。

峰值那条（memory.max_usage_in_bytes / memory.peak）无输出——cgroup v2 的 memory.peak 需要 kernel ≥ 5.19，AutoDL 内核不满足，只能放弃历史峰值取证。

第三步：对照两种下载方式的内存行为

方式 传输机制 内存占用
wget（SAM） 普通 HTTP，流式写盘 几乎为零，只留 TCP 缓冲
新版 hf CLI（SD） huggingface_hub 1.x 默认走 Xet 并行分块先堆内存再落盘，可到数 GB

结合 2GB 上限，怀疑对象明确：Xet。

根因

huggingface_hub 1.x 引入了 Xet 传输协议，用于加速大文件下载：文件被切成并行分块，多个连接同时拉取，分块先缓存在内存里，再统一写盘。官方 issue 里有实测，下载期间内存占用能从 ~240MB 涨到 ~4GB。

无卡模式容器上限 2GB，Xet 一加速内存直接顶破 cgroup 限制，OOM killer 发 SIGKILL，终端打印 Killed。这就解释了全部现象：

  • 为什么单独跑也 Killed：Xet 自己就能把内存堆到 2GB 以上，不需要和其他进程抢；
  • 为什么 wget 没事：流式写盘，内存不涨；
  • 为什么文档里 pin 的旧版 huggingface-cli（huggingface_hub 0.25.0）没事：那个版本没有 Xet，换新 hf CLI 才触发。

解决

首选：关掉 Xet，退回普通 HTTP 流式下载

实测内存从数 GB 降到 ~200MB，下载不再被 Killed。代价是丢掉 Xet 的加速，但普通 HTTP 在镜像源下速度足够。

想保留加速：降 Xet 并发

并发降为 2 后，内存峰值显著下降，多数低配实例可接受。

验证

关闭 Xet 后重跑下载，一次通过，未再出现 Killed。下载本身有断点续传，前面的部分直接接着下，不重头开始。

无卡模式 2GB 上限的连带影响

这次排查确认无卡模式内存是 2GB 硬上限，对后续操作有两处直接约束：

  • 不要在无卡模式做推理或训练。SAM 权重 2.6GB，光 torch.load 就顶破 2GB，必被 OOM。跑实际脚本要切回有卡模式，GPU 实例内存远大于 2GB。
  • 编译 C++ 项目注意峰值内存（比如编译 diffvg 这类带子模块的项目）。万一 make 被 Killed，改成 make -j1 单线程编译，峰值内存会降下来。

结论

AutoDL 无卡模式 2GB 内存 + huggingface_hub 1.x 默认 Xet 并行下载，组合成稳定复现的 OOM Killed。识别它的关键点在于：Killed 是 SIGKILL 而非报错退出，而容器环境 dmesg 不可用，只能靠 cgroup 限制文件确认内存上限，再用「wget 能下完、hf 必死」的对照锁定传输层差异。最终用 HF_HUB_DISABLE_XET=1 一次性解决。
